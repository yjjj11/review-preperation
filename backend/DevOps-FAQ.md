## Docker 篇

### 1. Docker 是什么？和虚拟机有什么区别？

**Q:** 容器化技术 Docker 和传统虚拟机本质区别是什么？为什么容器更轻更快？

**A:**

**Docker 定义：** Docker 是一种**操作系统层面的虚拟化技术**，也叫容器化技术，让应用可以打包成镜像，在任何环境一致运行，解决"我本地能跑你机器不能跑"的环境不一致问题。

**Docker 和虚拟机区别：**

| 对比维度 | 容器（Docker） | 虚拟机（VM） |
|----------|---------------|-------------|
| **虚拟化层次** | 操作系统级虚拟化，共享宿主机内核 | 硬件级虚拟化，模拟完整硬件，运行独立完整操作系统 |
| **启动速度** 秒级（几秒钟） | 分钟级（几分钟） |
| **资源占用** 非常轻量，只有应用本身和依赖，MB 级 | 很重，每个 VM 都要完整 OS，GB 级 |
| **性能** 接近原生，几乎无损耗 | 有一定性能损耗 |
| **隔离性** 进程级隔离，共享内核，隔离性 weaker | 系统级隔离，安全性 stronger |
| **部署密度** 一台机器能跑几百上千个容器 | 一台机器只能跑十几个VM |

**一句话总结：** 容器=App + 依赖 + 配置，共享内核，轻量快；虚拟机=完整操作系统 + App，资源重，启动慢。

### 2. Docker 镜像是什么？什么是分层镜像？

**Q:** Docker 镜像为什么分层？分层好处是什么？

**A:**

**Docker 镜像定义：** 镜像就是一个**只读的模板**，包含了运行应用所需的所有内容：代码、依赖库、环境变量、配置文件等，是容器的静态模板。

**分层结构：** Docker 镜像采用分层构建，每一条 Dockerfile 指令就是一层，所有层堆叠在一起，从下到上依次是：
- 基础镜像层（比如 ubuntu/alpine）
- 依赖安装层（pip/npm/apt 安装依赖）
- 代码添加层（把项目代码加进去）
- 配置层（暴露端口、设置启动命令）

**分层的核心好处：** **复用+节省空间**，不同镜像可以共享相同的基础层，比如多个镜像都用 alpine 基础镜像，磁盘上只存一份，pull/push 也只传变化的层，节省带宽和存储空间。

### 3. Docker 镜像和容器区别是什么？

**Q:** 镜像和容器傻傻分不清楚？一句话说清楚区别？

**A:**

- **镜像（Image）**：只读静态模板，相当于"类"，程序没运行，存放在磁盘上
- **容器（Container）**：镜像运行起来的实例，相当于"对象"，有独立进程空间，运行时会在只读镜像最上层加一个可写层，是动态运行的
- **关系**：一个镜像可以创建多个容器，每个容器互相隔离。

### 4. Dockerfile 常见指令有哪些？分别什么作用？

**Q:** 写 Dockerfile 常用哪些指令？

**A:**

| 指令 | 作用 |
|------|------|
| `FROM` | 指定基础镜像，第一条必须是 FROM |
| `WORKDIR` | 设置工作目录，后续指令都在这个目录执行 |
| `COPY` / `ADD` | 把本地文件复制到镜像里，ADD 支持自动解压压缩包 |
| `RUN` | 构建镜像时执行命令（比如安装依赖） |
| `EXPOSE` | 声明暴露端口，告诉 Docker 容器监听什么端口，只是文档声明，不自动映射 |
| `ENV` | 设置环境变量，运行时容器可以读取 |
| `CMD` | 容器启动时默认执行的命令，可以被 docker run 覆盖 |
| `ENTRYPOINT` | 容器入口，不会被覆盖，和 CMD 配合可以做默认参数 |

**CMD vs ENTRYPOINT 区别：**
- CMD 可以被 `docker run` 后面的命令覆盖
- ENTRYPOINT 不会被覆盖，总是会执行
- 如果都写，CMD 会变成 ENTRYPOINT 的默认参数

### 5. 什么是 Docker 数据卷？为什么需要数据卷？

**Q:** 容器里数据默认会随着容器删除丢失，怎么持久化？

**A:**

**数据卷（Volume）** 是 Docker 提供的数据持久化方案，把容器内的数据挂载到宿主机文件系统，容器删除数据还在，实现容器数据持久化。

**为什么需要数据卷：**
1. **数据持久化**：容器删除后数据不丢失，容器重启数据还在
2. **共享数据**：多个容器可以共享同一个数据卷，交换数据
3. **避开容器联合文件系统**：容器读写层性能不如直接读写宿主机文件系统，大数据量用数据卷性能更好

**三种挂载方式：**
- **数据卷（Volume）**：Docker 管理，存在宿主机 `/var/lib/docker/volumes/`，推荐用
- **绑定挂载（Bind Mount）**：挂载宿主机任意路径到容器，开发常用，把代码目录挂进去热更新
- **tmpfs 挂载**：挂载到内存，不持久化，敏感数据用完就丢，安全

### 6. Docker 有哪几种网络模式？

**Q:** Docker 默认网络模式有哪几种？各自适用场景？

**A:**

Docker 默认有 5 种网络模式：

1. **bridge 桥接网络（默认）**：
   - Docker 默认网络，会创建 docker0 网桥，容器通过虚拟网卡和网桥通信，NAT 访问宿主机外网
   - 适用：单机容器之间互相通信，最常用

2. **host 主机网络**：
   - 共享宿主机网络栈，不隔离网络，容器直接用宿主机 IP 和端口
   - 适用：性能要求极高的场景，缺点端口会冲突，只能一个容器绑定该端口

3. **none 无网络**：
   - 禁用网络，只有 lo 回环网卡，没有外网
   - 适用：不需要网络的任务（比如批量计算任务），安全

4. **container 容器网络**：
   - 和一个已经存在的容器共享网络栈
   - 适用：Pod 概念原型，多个容器共享网络，K8s Pod 里多个容器就是这种

5. **overlay 覆盖网络**：
   - 跨主机集群网络，多机器 Docker  Swarm 集群容器互通
   - 适用：多节点集群容器通信

### 7. 容器之间怎么通信？容器和宿主机怎么通信？

**Q:** 默认 bridge 模式下，两个容器怎么互相访问？

**A:**

**容器之间通信：**
- 同一个 bridge 网络下，可以**通过容器 IP 直接访问**；
- 也可以**通过容器名/服务名**访问，Docker 内置 DNS 服务解析。

**容器和宿主机通信：**
- 容器访问宿主机：通过 `host.docker.internal`（Docker 18.03+）解析到宿主机 IP；
- 宿主机访问容器：需要做端口映射 `-p 宿主机端口:容器端口`，通过宿主机 IP+端口访问容器。

### 8. 什么是 docker-compose？解决什么问题？

**Q:** 本地开发多个容器怎么一起启动？docker-compose 作用是什么？

**A:**

`docker-compose` 是 Docker 官方推出的**多容器编排工具**，用一个 YAML 文件定义多个容器组成的应用，一键启动/停止所有服务，不用一个个手动跑 docker run。

**解决的问题：**
- 本地开发环境，一个应用需要多个容器（web+db+cache），不用逐个手动启动，一个命令全部起来
- 不同开发人员环境一致，clone 代码 `docker-compose up` 直接跑
- 适合本地开发、测试环境，简单编排够用

**常用命令：**
- `docker-compose up -d` 后台启动所有服务
- `docker-compose down` 停止删除所有容器
- `docker-compose logs -f` 查看日志

### 9. 怎么查看容器日志？怎么进入运行中容器？

**Q:** 容器起不来怎么排查？

**A:**

- **查看容器日志**：`docker logs 容器ID`，`docker logs -f 容器ID` 持续跟踪日志
- **进入容器**：`docker exec -it 容器ID /bin/bash` 或者 `docker exec -it 容器ID sh`（alpine 镜像没有 bash）
- **查看容器详情**：`docker inspect 容器ID` 看配置、网络、挂载信息

---

### 10. Docker 怎么限制容器 CPU/内存资源？

**Q:** 防止容器把宿主机资源吃光，怎么限制？

**A:**

启动容器时用参数限制：

- **内存限制**：`docker run -m 1g --memory-swap 1g` 限制最多用 1GB 内存
- **CPU 限制**：`docker run --cpus 2` 限制最多用 2 核 CPU，`--cpu-shares 512` 按比例分配（相对权重，默认 1024）
- **磁盘 IO 限制**：`--device-read-bps`、`--device-write-bps` 限制读写速度

## Kubernetes 基础篇

### 11. Kubernetes 是什么？为什么需要它？

**Q:** K8s 解决什么问题？为什么现在后端开发都需要容器编排？

**A:**

**Kubernetes（K8s）** 是 Google 开源的**容器编排系统**，用来自动化部署、扩容缩容、管理容器化应用。

**解决的核心问题：**
1. **自动化部署调度**：成百上千个容器，自动调度到合适节点，不用手动部署
2. **自我修复**：容器挂了自动重启，节点挂了自动把 Pod 调度到其他节点
3. **弹性伸缩**：根据负载自动扩容缩容，峰值扩容，低谷缩容，节省资源
4. **服务发现与负载均衡**：内置 DNS 服务发现，不用自己写服务注册发现
5. **滚动更新**：不宕机更新版本，更新过程不影响用户使用，可以一键回滚
6. **统一管理大规模集群**：几千台机器的容器集群，统一管控

**一句话：** K8s 就是大规模容器集群的操作系统，帮你自动管好所有容器，让应用高可用。

---

### 12. K8s 核心组件有哪些？分别什么作用？

**Q:** Master 节点和 Node 节点都跑什么组件？

**A:**

K8s 集群分两种角色：**Master 节点**（控制面）和 **Node 节点**（工作面）。

**Master 节点核心组件：**
- **kube-apiserver**：集群入口，所有操作都通过它，提供 REST API，认证授权，是集群的网关
- **etcd**：分布式键值存储，保存集群所有状态数据（配置、元数据），是 K8s 的"数据库"
- **kube-scheduler**：调度器，新 Pod 出来了，选一个合适的 Node 节点去运行
- **kube-controller-manager**：控制器管理器，运行各种控制器（节点控制器、Pod 控制器、Service 控制器），维护集群状态
- **cloud-controller-manager**：云服务商控制器，对接云厂商 API 管理负载均衡、存储等

**Node 节点核心组件：**
- **kubelet**：每个 Node 上都跑一个 kubelet，负责和 Master 通信，管理本机 Pod，拉镜像、启动容器、汇报节点状态
- **kube-proxy**：每个 Node 上都跑一个网络代理，负责 Service 网络路由、负载均衡，把 Service 请求转发到后端 Pod
- **容器运行时**：Docker/containerd，真正跑容器的

### 13. Pod 是什么？为什么需要 Pod？

**Q:** K8s 最小调度单位为什么是 Pod 不是容器？一个 Pod 多个容器怎么理解？

**A:**

**Pod 是 K8s 最小的调度单位**，可以理解成"逻辑主机"，一个 Pod 里可以跑一个或多个容器（通常一个 Pod 跑一个主容器，也可以多个容器协同）。

**为什么需要 Pod 而不是直接调度容器：**
- 因为有些场景需要多个容器紧密协作，它们必须跑在同一个节点上，共享网络、共享存储，比如：
  - **主容器 +  sidecar 容器**：日志收集、代理、监控，sidecar 和主容器一起生命周期绑定
  - 同一个 Pod 里的容器共享：共享网络命名空间（可以用 localhost 通信）、共享数据卷
- Pod 把紧密协作的一组容器打包成一个调度单元，一起调度到同一个节点，非常方便

**一个 Pod 多个容器最佳实践：** 只有真正需要一起运行的容器才放一个 Pod，不要把不相关的容器塞进去，一般一个 Pod 一个主容器，最多加一两个 sidecar。

### 14. 讲一下 Pod 生命周期？

**Q:** Pod 从创建到销毁经历哪些阶段？

**A:**

Pod 生命周期主要阶段：
1. **Pending（挂起）**：API Server 已经接受了 Pod 创建请求，还没调度成功，或者镜像还在拉取
2. **Running**：Pod 已经调度到节点，所有容器都已经启动，至少一个容器还在运行
3. **Succeeded（成功）**：所有容器都已经成功退出，并且是正常退出（exit code 0），一般是 Job 任务跑完会到这个状态
4. **Failed（失败）**：所有容器都退出了，至少有一个容器异常退出（exit code ≠ 0）
5. **Unknown（未知）**：Master 收不到 Node 的状态汇报，不知道 Pod 现在啥状态，一般是 Node 网络不通

**Pod 中容器的四种探针：**
- **启动探针（livenessProbe）**：判断容器是否启动完成，启动没完成不处理请求，保护慢启动应用
- **存活探针（livenessProbe）**：判断容器是否活着，如果探针失败，kubelet 会重启容器，解决死锁问题
- **就绪探针（readinessProbe）**：判断容器是否就绪，能不能接收请求，如果没就绪，Service 会把这个 Pod 从负载均衡去掉，不把流量转给它

**探针检测方式：** `HTTPGet`（调 HTTP 接口返回 2xx 成功）、`TCPSocket`（TCP 连接成功就算活）、`Exec`（执行命令退出码 0 成功）。

### 15. Deployment、StatefulSet、DaemonSet、Job/CronJob 区别？各自适用场景？

**Q:** K8s 几种工作负载怎么选？

**A:**

| 资源类型 | 特点 | 适用场景 |
|----------|------|----------|
| **Deployment** | 无状态应用，Pod 都是一模一样，没有顺序，没有身份，可以随便调度随便删 | 网站、API 服务、微服务，绝大多数应用都用这个 |
| **StatefulSet** | 有状态应用，每个 Pod 有稳定的唯一身份（网络名、存储），有序启动有序删除 | 有状态服务：数据库（MySQL/Redis）、ZooKeeper、ETCD、需要稳定存储的应用 |
| **DaemonSet** | 每个 Node 节点上都跑一个 Pod，新节点加入自动跑一个 | 节点级后台任务：日志收集（Fluentd）、节点监控（Prometheus Node Exporter）、网络插件（CNI） |
| **Job** | 一次性任务，跑完就结束，Pod 退出不重启 | 批量数据处理、数据导导导入、一次性任务 |
| **CronJob** | 定时任务，按照时间周期重复执行 | 定时备份、定时报表、定时清理日志 |

### 16. Service 是什么？有几种类型？怎么工作的？

**Q:** K8s 为什么需要 Service？Pod IP 会变怎么访问？

**A:**

**Service 是 K8s 提供的**负载均衡/服务发现抽象**，解决 "Pod 会漂移，IP 会变，怎么稳定访问" 的问题。

**工作原理：**
- Service 给一组相同 Pod 提供一个**统一的固定访问入口（Cluster IP）**
- Kube-proxy 监听 Service 和 Pod 变化，维护节点上的路由规则/iptables，把请求负载均衡到后端 Pod
- 不管 Pod 怎么漂移重启，Service 的 Cluster IP 不变，客户端只用访问 Service IP 就行

**Service 四种类型：**
1. **ClusterIP（默认）**：只在集群内部通，只有集群内其他 Pod 能访问，外部不能访问，最常用
2. **NodePort**：在每个 Node 上开一个端口（30000-32767），集群外可以通过 `NodeIP:NodePort` 访问，适合测试/小场景
3. **LoadBalancer**：云厂商集成，自动创建云厂商的负载均衡，把流量导进来，生产环境对外暴露服务用这个
4. **ExternalName**：把集群外服务引入集群，给一个 DNS 名字，就是个 CNAME 记录

### 17. Ingress 是什么？和 Service 区别？

**Q:** 为什么有了 Service 还要 Ingress？

**A:**

**Ingress 是 K8s 提供的**七层负载均衡**，用来对外暴露 HTTP/HTTPS 服务，支持基于域名的路由，可以把多个服务收敛到一个入口。

**和 Service 区别：**
- Service 是**四层负载均衡**，工作在 TCP/IP 层，负责把请求从 ClusterIP 负载均衡到 Pod；
- Ingress 是**七层负载均衡**，工作在 HTTP 层，能根据域名、路径路由到不同 Service；

**为什么需要 Ingress：**
- 如果不用 Ingress，每个 Service 对外暴露都要用 NodePort 或者 LoadBalancer，每个 Service 一个公网 IP，成本太高；
- 用 Ingress，一个公网 IP 入口，根据域名路径路由到不同 Service，节省公网 IP，还能做 SSL 终止、路径路由，非常方便。

**常见 Ingress Controller：** NGINX Ingress Controller（最常用）、Traefik。

---

### 18. ConfigMap 和 Secret 区别是什么？

**Q:** 配置信息放哪里？敏感信息放哪里？

**A:**

两者都是用来**把配置和镜像解耦**，不用把配置硬编码写到镜像里，不同环境用不同配置。

**区别：**
- **ConfigMap**：存**普通非敏感配置**，比如配置文件、环境变量、命令行参数，明文存储
- **Secret**：存**敏感数据**，比如密码、API Key、证书，会base64编码存储（不是加密，只是编码，需要加密存在 etcd 可以加密）

---

### 19. PV 和 PVC 是什么？怎么理解？

**Q:** K8s 持久化存储怎么设计？

**A:**

- **PV（PersistentVolume）**：是集群里的一块实际存储，由管理员提前创建好，或者 StorageClass 动态创建，是实际存储资源，相当于"磁盘分区"
- **PVC（PersistentVolumeClaim）**：是用户对存储的请求，Pod 要用存储就声明一个 PVC，K8s 会帮你绑定一个满足要求的 PV，相当于"申请磁盘"

**分离好处：** 管理员管理底层存储，开发只用申请存储，不用关心底层是云盘还是 NAS，解耦了存储供应和使用。

**常用：** 云厂商动态 provisioning，你声明 PVC，K8s 自动帮你创建云盘，挂载给 Pod，不用管理员手动提前创建 PV。

## Kubernetes 进阶篇

### 20. K8s 调度流程讲一下？

**Q:** 一个新 Pod 来了，kube-scheduler 怎么选节点？

**A:**

kube-scheduler 分两步选节点：

**第一步：过滤（Predicate）**：把不满足条件的节点过滤掉，比如：
- 资源不够的过滤掉
- 亲和性规则不满足过滤掉
- 已经太多 Pod 负载太高过滤掉
- 匹配污点容忍，不匹配的过滤掉

**第二步：打分（Priority）**：对剩下的候选节点打分，分最高的胜出：
- 优先级算法打分，比如：
  - 资源 request 越少，分越高（让资源使用率更均衡）
  - 亲和性满足加分
  - 节点越空闲，分越高
- 选出分最高的那个节点，把 Pod 绑定过去

---

### 21. 什么是节点亲和性、Pod 亲和性、污点容忍？怎么用？

**Q:** 我想让 Pod 调度到特定节点，怎么配置？

**A:**

**节点亲和性（NodeAffinity）**：根据 Node 标签，把 Pod 调度到满足条件的 Node 上，比如：
- 要求 Node 有 `disk=ssd` 标签，就把需要高性能存储的 Pod 调度到 SSD 节点；
- 分 `requiredDuringSchedulingIgnoredDuringExecution`（必须满足，不满足不调度）和 `preferredDuringSchedulingIgnoredDuringExecution`（尽量满足，没有也能调度）。

**Pod 亲和性/反亲和性（PodAffinity/PodAntiAffinity）**：根据已经运行在 Node 上的 Pod 标签，决定能不能调度：
- **亲和性**：我这个 Pod 要和带某个标签的 Pod 跑在一起，比如前端和缓存放一起，降低网络延迟；
- **反亲和性**：我这个 Pod 不要和带某个标签的 Pod 跑在一起，比如同一个服务的多个 Pod 分散到不同节点，提高可用性。

**污点（Taint）和容忍（Toleration）**：污点是 Node 身上贴的标签，表示"不欢迎没有容忍这个污点的 Pod 过来"，作用是**排斥 Pod 不调度过来**：
- 比如 Master 节点默认打了污点，普通 Pod 不会调度到 Master，只有容忍了这个污点的 Pod 才能过来；
- 比如专用节点，给特定业务留着，打上污点，只有业务 Pod 加容忍才能来。

**一句话总结：**
- 亲和性 = Pod 主动找**想要**的节点/Pod
- 污点容忍 = Node 主动排斥**不想要**的 Pod

### 22. 什么是 HPA？怎么工作的？

**Q:** K8s 自动扩缩容怎么实现？

**A:**

**HPA（Horizontal Pod Autoscaler）** 就是**Pod 水平自动扩缩容**，根据监测到的 CPU 使用率/自定义指标，自动调整 Deployment 的 Pod 数量。

**工作流程：**
- HPA 控制器每隔一段时间（默认 15 秒）查询指标（比如 CPU 使用率）
- 如果平均 CPU 使用率超过了你设置的阈值（比如 70%），就增加 Pod 副本数
- 如果降到阈值以下，就减少 Pod 副本数
- 支持根据自定义指标（比如 QPS、内存）扩缩容

**注意：** HPA 是**水平扩缩容**，增加减少 Pod 数量；还有 VPA（Vertical Pod Autoscaler）是垂直扩缩容，调整单个 Pod 的 CPU 内存 requests/limits。

### 23. K8s 滚动更新怎么实现？回滚怎么做？

**Q:** 发布新版本怎么做到不宕机？更坏情况怎么回滚？

**A:**

**滚动更新（RollingUpdate）** 是 Deployment 默认更新策略：
- 先启动新版本 Pod，就绪之后再杀掉一个旧版本 Pod
- 一步步把旧版本 Pod 全部换成新版本，整个更新过程，始终有可用 Pod 对外服务，不会停机
- 可以配置 `maxSurge`（最多超过期望副本数几个）和 `maxUnavailable`（最多不可用几个）控制更新速度

**回滚：** Deployment 会保存所有版本的 ReplicaSet 历史，每个版本保留完整配置，如果你发现新版本有问题，`kubectl rollout undo deployment/xxx` 一键回滚到上一个版本，非常方便。

### 24. K8s 健康检查有哪几种？为什么需要健康检查？

**Q:** 容器启动了但是程序卡了，服务不能用，K8s 怎么知道？

**A:**

K8s 三种探针做健康检查：

| 探针 | 作用 | 失败了怎么办 |
|------|------|--------------|
| **启动探针（StartupProbe）** | 判断应用是否已经启动完成 | 失败了 kubelet 杀掉容器，重启；成功了就绪探针才开始工作，保护慢启动应用，避免还没启动就进去流量 |
| **存活探针（LivenessProbe）** | 判断应用是否还活着（会不会死锁了进程还在） | 失败了 kubelet 杀掉容器，重启，解决应用死锁问题 |
| **就绪探针（ReadinessProbe）** | 判断应用是否就绪，能不能接收流量 | 失败了，K8s 把这个 Pod 从 Service 的 endpoints 里摘掉，不把新流量转给它，直到就绪了再加回来 |

**为什么需要健康检查：** 应用启动可能慢，或者死锁了进程还在，K8s 不知道服务不能用，还会继续转发流量，导致用户请求失败，健康检查就是让 K8s 知道服务真的可用了，不可用了就把它拿掉。

### 25. 什么是 RBAC？K8s 怎么权限控制？

**Q:** RBAC 权限模型怎么理解？

**A:**

**RBAC（Role-Based Access Control）** 基于角色的访问控制，是 K8s 默认的权限控制方式。

**四个核心概念：**
- **Role（角色）**：定义一组权限，比如能对哪些资源做哪些操作（get/list/create/delete），Role 是命名空间级别的
- **ClusterRole**：集群级别的角色，权限作用整个集群，不是某个命名空间
- **RoleBinding（角色绑定）**：把 Role 绑定给用户/Group/ServiceAccount，让这个用户拥有 Role 的权限，RoleBinding 也是命名空间级
- **ClusterRoleBinding**：把 ClusterRole 绑定给用户，作用整个集群

**好处：** 权限拆分，可以给不同用户/服务账号分配不同粒度的权限，最小权限原则，安全。

---

### 26. etcd 为什么用来存 K8s 数据？etcd 是什么特点？

**Q:** K8s 为什么用 etcd 不用 MySQL/ZooKeeper？

**A:**

etcd 是一个**强一致的分布式键值存储**，天生适合存集群元数据。

**为什么 K8s 选 etcd：**
1. **强一致性**：基于 Raft 共识算法，所有节点读写一致，选主、配置存储都需要强一致，不能脑裂
2. **HTTP API**：提供简单 RESTful API，使用方便
3. **Watch 机制**：支持监听键变化，K8s 组件可以监听配置变化，实时更新
4. **安全**：支持 SSL/TLS 认证，安全存储敏感数据

**对比 ZooKeeper：** etcd 更简单，Raft 比 ZAB 更容易理解实现，API 更友好，现在云原生生态 etcd 是标准。

### 27. K8s 怎么实现服务发现？

**Q:** 新服务启动，其他服务怎么找到它？

**A:**

K8s 内置服务发现：
1. 每个 Service 创建时会在 K8s DNS 里注册一条域名记录 `service-name.namespace.svc.cluster.local`
2. 客户端只用通过这个域名访问，DNS 会解析到 Service 的 Cluster IP
3. kube-proxy 再把请求负载均衡到后端健康的 Pod，完成服务发现

整个过程都是内置的，开发不用自己做服务发现，直接用域名访问就行。

### 28. 什么是 CNI？

**Q:** K8s 网络插件是什么？CNI 是什么意思？

**A:**

**CNI（Container Network Interface）** 是容器网络接口标准，定义了容器网络插件应该怎么实现，K8s 用 CNI 来管理容器网络，给 Pod 分配 IP、设置路由。

**常见 CNI 插件：** Flannel、Calico、Weave。
- Flannel：简单，overlay 网络，适合大多数场景
- Calico：BGP 路由，性能更好，支持网络策略，安全控制哪个 Pod 能访问哪个，现在更常用

### 29. 说一下 K8s 四层和七层负载均衡区别？

**Q:** Service 和 Ingress 分别哪层？

**A:**

- **四层负载均衡（Service）**：工作在传输层（TCP/IP），只基于 IP + 端口做转发，不解析 HTTP 内容，性能高
- **七层负载均衡（Ingress）**：工作在应用层（HTTP），能解析 HTTP 请求，根据域名、路径路由到不同 Service，功能更丰富

K8s 一般架构：`用户请求 → Ingress（七层路由） → Service（四层负载均衡） → Pod`，分层处理。

## 总结速记

| 考点 | 核心结论 |
|------|---------|
| Docker vs VM | 容器共享内核，秒级启动，轻量；VM 完整操作系统，启动慢，重 |
| Docker 镜像分层 | 每一层 Dockerfile 指令一层，共享基础层，节省空间带宽 |
| 镜像 vs 容器 | 镜像是只读静态模板，容器是镜像运行实例 |
| 数据卷作用 | 数据持久化，容器删除不丢，多容器共享数据 |
| Docker 网络模式 | bridge（默认单机互通）、host（共享宿主机网络）、none（无网络） |
| K8s 核心组件 | Master：apiserver/etcd/scheduler/controller-manager；Node：kubelet/kube-proxy |
| Pod 概念 | K8s 最小调度单位，一个 Pod 可以多个容器共享网络存储 |
| Deployment 适用 | 无状态应用，微服务/API 服务，绝大多数场景 |
| StatefulSet 适用 | 有状态应用，数据库/ZK，需要稳定网络存储 |
| DaemonSet 适用 | 每个节点一个，日志收集/节点监控 |
| Service 作用 | 给一组 Pod 提供固定访问入口，负载均衡，解决 Pod IP 漂移问题 |
| Service 类型 | ClusterIP 内部访问（默认）、NodePort 节点端口、LoadBalancer 云厂商LB |
| Ingress vs Service | Ingress 七层HTTP路由，Service 四层负载均衡，一个入口暴露多个服务 |
| ConfigMap vs Secret | ConfigMap 存普通配置，Secret 存敏感信息 |
| PV/PVC | PV 实际存储，PVC 存储申请，解耦存储供应和使用 |
| 亲和性 vs 污点 | 亲和性 Pod 主动选节点，污点节点排斥 Pod |
| HPA | 根据CPU/QPS自动水平扩缩Pod数量 |
| 三种探针 | 启动探针（判断启动完）、存活探针（死了重启）、就绪探针（不能接流量就摘掉） |
| RBAC | 基于角色权限控制：Role定义权限，RoleBinding绑定给用户 |
| etcd | 强一致分布式KV，存K8s集群所有状态，Raft共识 |
