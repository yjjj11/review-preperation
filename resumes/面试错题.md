·如果你发现一个在windows上开发的程序到了linux平台就无法正常运行了，你认为可能是什么原因导致的？
1.操作系统 API / 系统调用 差异（最核心）
2.文件系统差异：路径分隔符：Windows：\ 反斜杠，Linux：/ 正斜杠，硬写死路径导致文件找不到。Windows 文件默认大小写不敏感，linux严格大小写。换行符差异Windows：\r\n；Linux：\n
3.编译差异：例如一些特有的编译语法跨平台无法识别；库的后缀不同，链接时错误；有些包为平台专属，跨平台无替代
4.字符编码差异：windows/GBK, Linux/UTF-8,导致中文日志、配置、字符串乱码、解析失败。

·如果你发现一个程序在debug模式下是可以运行的，但是release模式下却发生了报错，那么可能的原因是哪些 ？
Debug：不优化、带调试信息、内存初始化、栈检查严格
Release：O2 优化、速度优先、去掉安全检查、内存不初始化
程序 Debug 正常、Release 报错，本质是：Debug 的安全机制掩盖了 bug，Release 去掉保护后暴露。
1.未初始化变量：debug模式会自动填0,不乱码，release模式下不初始化是随机垃圾值，可能会导致随即跳转，崩溃
2.编译器优化：release模式下O2优化可能导致无效代码删除，指令重排，如果某些线程间依赖顺序执行，那么优化后可能会有未定义行为
3.多线程问题：debug模式跑的慢，缩小了锁竞争问题，release模式跑得快，可能死锁竞争加剧。
4.宏定义问题：在代码中加入了一些debug的宏定义代码段，导致模式切换后代码不执行或多余执行。


·你熟悉的检查内存泄漏的工具有什么？
1 .GDB 是 Linux 下 C++ 标准调试工具，我主要用它分析程序崩溃、查看调用栈、分析 core dump 文件，是定位各种复杂问题的基础工具。
2 .ASan内置在编译器中，编译时开启即可，用于快速检测栈缓冲区溢出、use-after-free、重复释放、野指针，访问未初始化内存，内存泄漏等内存错误。
只需要在编译的时候加上编译选项   -fsanitize=address,leak,undefined
例如-栈缓冲区溢出：数组访问越界等，会显示崩溃栈
例如-use-after-free：会显示在哪里UAF，哪里释放，哪里分配的调用栈
要点：开发阶段必开，但是上线关闭，因为会变慢，耗内存。

·当你的容器突然无法访问宿主机数据库的时候你的排查思路是怎样的？
前提：容器是bridge模式，mysql运行在宿主机上本地，docker exec 基于宿主机本地 docker.sock 通信，不依赖容器网络与网卡；因此即使容器网卡损坏、无 IP、网络完全不可用，依旧可以正常进入容器排查
1.先本地telnet一下3306端口，看看服务是否正常。如果不正常就是数据库问题，重启
2.那么进入容器内部，ipaddr一下检查自身网络状态，ip是否正常，排查容器网桥路由、网络模式异常，必要时使用 host 网络模式验证；
3.ping一下宿主机ip，看看网络是否连通。注意要用网桥地址而不是本地回环。如果ping不通那可能是防火墙的问题。修复容器宿主连通性后检查3306端口是否连通，如果不通可能是宿主机拦截了本端口。
4.如果连通但是连接不上，可能是宿主机数据库只监听127.0.0.1，修改监听地址到全部网段。如果还是不行，那可能是数据库账号远程访问权限未打开，需要授权。最后可能是容器内的数据库连接配置有问题。

·websocket和HTTP的区别是什么，以及websocket是怎样升级过去的？
区别：
HTTP 是短连接、单向问答模式，服务端不能主动推送；
WebSocket 基于 TCP 长连接、全双工通信，双方可实时互发数据，传输开销更小，适合实时业务。
升级过程:
WebSocket 通过HTTP 握手升级实现：客户端携带 Upgrade/Connection/Sec-WebSocket-Key 等头部发起 HTTP 请求；服务端校验合法后返回 101 Switching Protocols，完成协议切换；原有 TCP 连接持续复用，后续基于 WebSocket 帧进行双向长连接通信。


·c++为什么要内存对齐？
1.Cpu一般只能读取4/8的倍数，如果变量没对齐，地址在非倍数位置，cpu可能需要读两次再加额外计算才能拿到，速度慢几十倍。结构体成员朝最大的对齐。

·编译器优化都干哪些事情？
编译优化的目标是程序更小更快，不浪费空间，不做多于操作，主要干的几件事：
1.删除定义但未使用的代码段；
2.尽可能的将频繁访问的局部变量、中间计算值缓存到 CPU 寄存器减少内存占用，因为cpu内存访问速度比寄存器要慢很多。
3.编译期直接计算固定常量表达式，运行时不再重复运算；
4.循环优化：把循环内不会变化的计算提到循环外部，避免每轮循环重复执行。
5.内存布局优化：自动重排结构体成员顺序、压缩内存布局、删除多余对齐填充 Padding；
6.指令重排与流水线优化在不破坏代码逻辑的前提下，调整指令执行顺序，适配 CPU 流水线，提升并行执行效率。
